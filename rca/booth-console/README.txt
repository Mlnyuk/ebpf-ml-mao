RCA Console — 오프라인 부스 시연

이 폴더 전체를 행사 노트북에 복사합니다. 설치·API 키·인터넷이 필요 없습니다.

START.html: 직접 조작하는 관제 콘솔
WATCH.html: 자막 없는 실제 화면 녹화 반복 재생
RCA-CONSOLE.mp4: 일반 동영상 재생기용, 약 44초·무음
RCA-CONSOLE.webm: 브라우저용, MP4와 같은 녹화·무음

조작 순서
AI의 조사 보기 → 판단 근거 열기 → 처음으로
AI 판단의 [1] 서비스 설정 / [2] 연결 시도를 누르면 실제 인용 원문이 열립니다.
로그 행을 누르면 그 행의 원문을 열 수 있습니다.
원문 패널에서 Esc를 누르면 돌아갑니다.

단축키
1: 사건 개요 / 2: 저장된 조사 / 3: 실행 비교
/: 로그 검색 / R: 초기화 / Esc: 원문 닫기 또는 검색 입력에서 나오기

Python 로컬 서버를 선호하면 이 폴더의 상위 위치에서:
python3 -m http.server 8765 --bind 127.0.0.1 --directory booth-console
http://127.0.0.1:8765/viewer/index.html?demo=1
Windows에서는 python3 대신 py를 사용할 수 있습니다.

대표 사건 9e4945e7170b4a58의 실제 저장 기록입니다.
포함 실행 efc0b3de7271822b1552 / 제외 실행 6c938d099e296bd28fa6.
설정 8080과 실제 연결 시도 9099를 대조합니다. 연결 결과는 미측정입니다.
그래프는 저장 로그를 초 단위로 집계한 오류 응답 로그의 줄 수입니다.
전체 서비스 요청 수·오류율·실시간 관측값을 뜻하지 않습니다.
화면의 비용은 과거 실행 기록이며 새 API 과금은 없습니다.
긴 자막·내레이션·음악을 추가하지 않았으며 원문은 변경하지 않았습니다.

진행자 설명 예시 (약 35~45초, 영상에는 삽입하지 않음)
[첫 화면]
“저장된 장애 조사 기록입니다. 로그에는 요청 실패가 남아 있지만,
어디에 연결하려 했는지는 없습니다.”
[AI의 조사 보기]
“AI가 조회한 자료입니다. 설정은 8080번 포트인데,
운영체제에서 관찰한 실제 연결 시도는 9099번으로 향했습니다.
eBPF가 로그에 없던 목적지 단서를 더한 겁니다.”
[판단 근거 열기]
“AI가 인용한 설정과 관측 기록을 직접 열 수 있습니다.
같은 사건에서 eBPF가 없던 실행은 목적지를 특정하지 못했습니다.
다만 연결 시도 기록이므로 연결 결과까지 확정하지는 않습니다.”
[처음으로]
“인터넷이나 새 API 호출 없이 같은 기록을 다시 보여줄 수 있습니다.”
