Kubernetes RCA 부스 시연 — 인터넷 없이 사용

가장 간단한 방법
1. 이 booth-demo 폴더 전체를 행사 노트북에 복사합니다.
2. 영상 중심 운영: RCA-DEMO.mp4를 동영상 재생기로 엽니다.
   또는 WATCH.html을 더블클릭하면 자막이 들어간 무음 영상을 반복 재생합니다.
   WATCH.html은 브라우저 코덱 차이에 대비해 WebM을 먼저 사용합니다.
3. 직접 조작: START.html을 더블클릭합니다. Chrome 또는 Edge 권장.
   AI의 조사 보기 → 판단 근거 열기 → 처음으로.
   포트 아래 '인용된 증거 원문 펼치기'로 실제 값의 원문 위치를 확인할 수 있습니다.

Python이 있는 노트북에서 로컬 서버로 여는 정확한 명령
booth-demo 폴더의 상위 폴더에서 실행:
  python3 -m http.server 8765 --bind 127.0.0.1 --directory booth-demo
Windows에서 python3 명령이 없으면:
  py -m http.server 8765 --bind 127.0.0.1 --directory booth-demo
브라우저 주소:
  http://127.0.0.1:8765/viewer/index.html?demo=1
종료: 터미널에서 Ctrl+C.
Python·Node·Kubernetes·API 키는 파일 직접 열기와 MP4 재생에 필요 없습니다.
행사 노트북에는 Playwright나 FFmpeg를 설치하지 않아도 됩니다.

대표 사건과 출처
사건: 9e4945e7170b4a58 / 2026-10-29 저장 수집
eBPF 포함: efc0b3de7271822b1552 / selective-ebpf / repeat 0
eBPF 제외: 6c938d099e296bd28fa6 / selective-no-ebpf / repeat 0
원본: paper-results/2026-10-29/analysis-v3/viewer/index.html의 내장 기록
실제 로그에는 request completed status=503과 dependency request failed가 있고,
목적지는 없습니다. Pod에 선언된 의존성은 10.233.61.222:8080,
eBPF 요약에는 10.233.61.222:9099로 연결 시도 40회가 있습니다.
동일 사건·같은 선택 조회 방식·같은 반복 번호의 두 기록이며,
공통으로 조회한 비-eBPF 증거가 동일함을 생성 시 검사합니다.
선정 사례 설명이며 전체 정확도 또는 통계적 eBPF 효과를 입증하는 영상은 아닙니다.
연결 시도와 연결 결과는 다릅니다. 연결 성공/실패, 설정 오류의 발생 경로는 미확인입니다.
화면의 원문은 AI에게 제공된 증거입니다. eBPF는 요약 원문이며,
커널 원시 이벤트 전체는 이 소형 배포본에 포함하지 않습니다.

약 40초 시연 멘트 — 화면 버튼 순서
[첫 화면 / 약 8초]
서비스 요청이 실패한 상황입니다. 로그에는 503 오류만 있고,
어디로 연결하려 했는지는 남아 있지 않습니다.
[AI의 조사 보기 / 약 12초]
저장된 AI는 설정과 로그, 자원 기록을 확인했습니다.
eBPF는 운영체제에서 연결 시도를 관찰해, 로그에 없던 목적지를 알려줍니다.
[판단 근거 열기 / 약 15초]
설정은 8080인데 실제 시도는 9099였습니다.
AI는 이 두 증거로 포트 불일치를 짚었습니다.
같은 사건에서 eBPF를 빼면 원인을 보류했습니다.
다만 연결 성공이나 실패까지 측정한 것은 아닙니다.
[처음으로 / 약 5초]
모두 저장 기록 재생이라 인터넷이나 새 API 호출 없이 다시 볼 수 있습니다.

영상은 실제 화면 조작을 녹화한 약 44초 분량이며 무음·한국어 자막 방식입니다.
RCA-DEMO.srt는 자막 원문 보관용입니다. MP4에 자막이 이미 들어 있으므로
재생기에 외부 SRT를 추가하면 자막이 두 번 보일 수 있습니다. WebM에도 자막이 들어 있습니다.
manifest.json과 video-manifest.json에 출처·파일 해시·녹화 검증 정보를 보존합니다.
