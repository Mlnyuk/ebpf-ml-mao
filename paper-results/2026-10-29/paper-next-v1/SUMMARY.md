# 후속 연구 결과 — paper-next-v1

기존 paper-clock-v3의 126개 실행·실패·프로토콜을 보존하고, 2026-10-29 05:35 UTC에 새 코드와 평가 프로토콜을 고정한 뒤 새 사건을 수집했다. 외부 OpenRouter API의 `z-ai/glm-5.3-flash`, 제공자 `z-ai/fp8`, fallback 없음으로 실행했다. 논문 주장을 검토하기 위한 탐색적 후속 실험이며 확증 연구로 부르지 않는다.

**새 발생·수집 20건, 주 비교 조사 80건, 종속 견고성 조사 8건을 완료했다. 진단 품질은 독립 사람 채점 전이므로 미평가다.** 20건은 각각 새 Pod UID를 사용했지만 같은 공유 클러스터에서 수집했으므로 서로 다른 클러스터 20개나 통계적으로 완전히 독립인 표본이라는 뜻은 아니다.

## 무엇이 관측됐는가

주 비교는 같은 사건·원본 증거·모델·제공자·압축·출력 계약·수정 정책의 일괄 방식과 선택 조회 방식이다. 아래 각 행은 새 사건 20건이며, 작은 증거와 주변 포함 증거는 동일 사건에서 만든 종속 조건이다. LLM 반복은 사건·방식·증거 조건당 1회다. 실패나 수정 호출을 제외하지 않았다.

이번 새 비교는 두 방식 모두 eBPF 포함이다. eBPF 포함/제외의 기존 네 비교군과 구성요소 제거 실험은 이전 126건 재분석에서 분리 집계했다. 새 사건에서 eBPF 자체의 진단 기여도를 다시 분리 검증한 것은 아니다.

|---|---|---:|---:|---:|---:|

| 주변 3개 workload 포함: 21개 증거 | 선택 | 9,453.3 | 0.036691 | 43.7초 | 1 |

- 작은 증거에서 선택 조회는 토큰 **30.51% 증가**, 비용 **31.42% 증가**, 시간 **29.48% 증가**였다. 선택 방식도 20건 모두 6개 증거를 전부 조회했다.
- 주변 포함 조건에서는 선택 조회가 평균 7.1개 증거를 조회했다. 토큰 **52.18% 감소**, 비용 **44.89% 감소**였지만 시간은 **13.18% 증가**했다.
- 과거 사건 혼입과 수집 누락의 8개 조사는 위 주 비교와 분리했다. 해당 작은 표본에서는 선택 조회의 토큰·비용·시간이 모두 일괄보다 높았다. [분리 집계](report/SUMMARY.md)에 그대로 남겼다.
- 이 결과는 “증거 규모에 따라 선택 조회의 비용 효과가 달라진다”는 관측을 지지한다. **진단 품질을 유지하면서 줄였다는 주장, 일반적인 정확도 우위, 항상 빠르다는 주장은 아직 할 수 없다.**

전체 88건은 최초 최종 출력 84건, 모델 수정 후 통과 4건, 최종 형식 실패 0건이다. 형식 통과는 정답 판정이 아니다. 최초 출력·수정 요청·수정 응답을 모두 보존했다. 기존 126건의 실패 4건은 변경하지 않았다. 과거 중첩 증거 ID 검증 문제와 새 등록 방식의 차이도 버전 간 진단 성능 향상의 인과적 증명으로 해석하지 않는다.

## 데이터와 비교 범위

정상, 정상 목적지의 애플리케이션 오류, 잘못된 주 통신, 정상 보조 통신과 잘못된 주 통신의 혼합, 비핵심 보조 통신 오류의 5상황에 로그 정보량 2수준·부하 2수준을 조합했다. 20건 모두 의도한 정상·장애 효과를 별도 HTTP 관측에서 확인했다. 이 정답과 주입 기록은 Agent 입력에 전달하지 않았다. 실제 이전 사건을 넣은 과거 혼입 및 대상 로그/eBPF 수집 누락은 종속 변형이다.

부하는 초당 1회/4회의 제한된 조건이고, 주변 telemetry는 실제 트래픽이 있는 실험용 workload 3개다. 대규모 운영 환경이나 포화 부하로 일반화하지 않는다. eBPF는 계속 **연결 시도 목적지·포트·횟수**만 제공한다. TCP 성공·실패, 지연, 재전송은 측정하지 않았다. 원본 exported event부터 시간·UID·컨테이너 필터, summary, evidence ID를 재생 검증했고 20건 모두 일치했다. 커널/export 단계의 유실이 없음을 입증한 것은 아니다.

단순 목적지 비교기는 별도 오프라인 기준선이다. 정상 목적지의 애플리케이션 오류를 설명하지 못하며, 비핵심 통신의 목적지 불일치를 서비스 장애로 확정하지 않는다. 이 기준선을 Agent의 장애별 판단 규칙으로 사용하지 않았다.

K8sGPT **v0.4.41**의 기본 분석기와 선택적 Log 분석기를 확인했고, 별도 Kubernetes-visible 양성 대조를 시험했다. 새 사건 20건에 native scan을 실행하고, Pod·Service·Deployment·ReplicaSet·Log 분석기의 전체 실험 namespace 설명을 같은 API 모델·제공자로 실행했다. 대상 finding은 14건, 예상 로그 키워드 신호가 없는 조건은 6건이었다. 실제 설명 API 호출은 14회다. 이는 정확도 14/20 또는 미감지 6건이라는 뜻이 아니다. 오진·적절한 보류는 사람 채점 전 미평가다.

K8sGPT는 native live Kubernetes 데이터와 자체 프롬프트·영문 출력, 우리 방식은 고정 증거와 한국어 구조화 출력을 사용했다. 따라서 **native 지원 범위 탐색 비교**이며 동일 입력·출력의 통제 비교로 합산하지 않는다. K8sGPT의 `--no-cache`는 사용했지만 제공자의 prefix cache는 통제하지 않았다. 실제 cache usage를 별도 기록했다. [범위](report/k8sgpt-scope.json), [버전별 원본과 설정](protocol.json), [추가 해석 제한](audit/claim-scope.json)을 참고한다.

별도 상한은 480회·$2였으며 예산 내에서 종료했다. 비용 누락 응답은 0건이다. 주 실험의 수정 호출 토큰 43,384개와 cache 입력 55,488개는 전체 토큰에 이미 포함된 부분집합이다. 반복 입력/새 증거의 정확한 provider 토큰 배분은 반환되지 않으므로 byte attribution으로만 분리하고 이를 토큰 수로 부르지 않는다. 과거 중단 배치·기존 126건의 비용은 이 표에 포함하지 않았다.

저장된 원본을 대상으로 한 별도 오프라인 요약 재생에서 20사건 × 3회 측정의 사건별 중앙값을 다시 요약한 wall-time 중앙값은 **6.26ms**, CPU-time 중앙값은 **6.25ms**였다. 별도 메모리 계측의 최대 Python 추적 할당은 **1,881,017 bytes**였다. 입력은 메모리에 미리 적재했으며 파일 읽기·수집·디코딩·콜드 import·프로세스 전체 RSS는 제외했다. 공유 호스트에서 측정한 이 수치로 온라인 저오버헤드를 주장하지 않는다. [측정 계획과 원자료](offline-summary-benchmark/protocol.json).

**Tetragon 기본 비용, 관측 정책 비용, 요약기의 온라인 추가 비용, 서비스 영향은 미측정이다.** 별도 커널의 전용 환경이 확인되지 않아 공유 수집기와 정책을 끄는 대조 실험을 하지 않았다. GPU 노드는 사용하지 않았다.
